# Аудит безопасности Greek Verbs — 2 ноября 2026

Проверены локальный исходный код, API авторизации, SQLite, клиентское хранение прогресса, конфигурация Vercel и состав загрузки. Проверки выполнялись на локальном сервере с тестовыми аккаунтами. Публичный сайт, реальная PostgreSQL-база, права команды Vercel, журналы запросов и резервные копии недоступны для проверки в этой сессии.

Это аудит доступной реализации, а не гарантия отсутствия всех уязвимостей. Подтверждённые ошибки, усиление защиты и оставшиеся ограничения перечислены отдельно. Признаков состоявшегося взлома не обнаружено; журналы production не исследовались.

## Дополнительное усиление защиты

- В Vercel PostgreSQL подключается с `sslmode=verify-full` и доверенным CA (`PGSSLROOTCERT`, по умолчанию системное хранилище). Раньше проверка сертификата зависела от строки подключения и могла отсутствовать. Реальное подключение к production-базе не проверено; тест проверяет переданные параметры.
- SQLite создаётся с правами 0600; каталог новой базы — 0700. Это ограничивает чтение базы другими обычными пользователями ОС, но не администратором или процессами того же пользователя.
- Production-cookie использует префикс `__Host-`, Secure, HttpOnly, SameSite=Lax и Path=/, без Domain. После обновления потребуется повторный вход: старое имя cookie больше не используется.
- Добавлены CSP, запрет встраивания во фреймы, nosniff, no-referrer и отключение разрешений камеры/микрофона/геолокации. В Vercel добавлен HSTS без includeSubDomains.
- Убрано общее правило публичного кеширования, которое также совпадало с API. Для API оставлен `no-store, private`; подтверждённая утечка ответа через CDN не воспроизводилась. Клиентские файлы должны перепроверяться, версии URL обновлены для доставки исправлений.
- При возвращении во вкладку серверная сессия перепроверяется. Между вкладками работают BroadcastChannel и storage-сигнал. Пароли очищаются из скрытой формы при уходе со страницы авторизации. Это не защищает пароль от уже исполняющегося вредоносного кода того же origin.
- Проверка сессии в фоне не может разблокировать или перезаписать выполняющийся вход.
- Сценарий деплоя загружает явно разрешённые файлы приложения, API и медиа; служебные документы, `.env`, SQLite и тесты не попадают в загрузку. Дополнены исключения прямого деплоя через Vercel CLI.
- `psycopg[binary]` зафиксирован на версии 3.3.6. Запрос OSV для `psycopg==3.3.6` и `psycopg-binary==3.3.6` не вернул известных advisory. Это не полный анализ нативных библиотек, всех будущих транзитивных зависимостей или образа Vercel.

## Что остаётся открытым

### 1. P1 перед публичным запуском: почта не подтверждается

Можно зарегистрировать адрес, принадлежащий другому человеку: сервер проверяет формат, но не владение почтой. Это не даёт доступа к уже существующему аккаунту, однако позволяет заранее занять чужой адрес. Для исправления нужен поток подтверждения через одноразовую ссылку и настроенная отправка писем. Почтовый провайдер не подключён; отправка писем в рамках аудита не выполнялась.

### 2. P2: можно узнать, зарегистрирована ли почта

Повторная регистрация возвращает 409 `email_exists`, новая — успешный вход. Ограничение попыток снижает массовый перебор, но различие остаётся. Простая замена текста ошибки не устранит различие между созданной сессией и отказом. Полное исправление следует делать вместе с подтверждением почты: одинаковый ответ «проверьте почту», затем завершение регистрации через письмо. Различие во времени именно при входе исправлено отдельно.

### 3. P2: ограничение попыток может временно блокировать владельца

После 15 попыток для адреса за 15 минут блокируются и последующие правильные входы с этим адресом. Атакующий, знающий почту, может использовать это для временного отказа в доступе. Существующая сессия при этом не отзывается. Нужна отдельная политика защиты от перебора: сочетание ограничений по IP и аккаунту, постепенная задержка, проверка автоматизации или подтверждение по почте. Простое удаление ограничения по адресу ослабило бы защиту от распределённого перебора; текущая политика сохранена и явно отмечена.

### 4. P2: нет восстановления доступа и отзыва всех сессий

Доступны выход из текущей сессии и истечение через 30 дней. Нет подтверждённого восстановления пароля, смены пароля и кнопки выхода на всех устройствах. При краже действующей cookie пользователь не сможет самостоятельно отозвать все сессии через интерфейс. Для завершения требуется подтверждение владения почтой, одноразовые токены восстановления и серверный отзыв сессий.

### 5. Ограничение приватности IndexedDB на общем устройстве

Прогресс разных аккаунтов разделён ключами, но хранится незашифрованным в одном профиле браузера. Выход не удаляет прогресс — так выполняется требование сохранять его между входами. Другой человек с доступом к тому же профилю браузера или исполняющийся код того же origin может прочитать эти данные через инструменты разработчика. Это не серверное разграничение доступа и не изоляция между пользователями ОС. Клиентский прогресс также можно подделать, поэтому его нельзя использовать как доказательство выполнения платных заданий или основание для наград с денежной стоимостью.

### 6. P3: строгая CSP ограничена inline-обработчиками

Приложение широко использует `onclick` и аналогичные HTML-атрибуты. CSP блокирует посторонние скрипты и inline script-блоки, но сохраняет `script-src-attr 'unsafe-inline'` для текущего интерфейса. При будущей HTML-инъекции это может позволить исполнение обработчика. Эксплуатируемый путь XSS от текущих полей почты, пароля, поиска или параметра id не найден: почта выводится через textContent, поиск не вставляет запрос в HTML, id выбирает элемент из статического набора. Для полного ужесточения нужно перенести HTML-обработчики в addEventListener и удалить разрешение inline-атрибутов.

## Секреты и проверенные механизмы

- По шаблонам найдена локальная служебная переменная Vercel в игнорируемом `.env.local`. Значение не выводилось и не включалось в отчёт. Факт утечки самого токена не установлен.
- Проверены 47 исторических текстовых Git-объектов на приватные ключи, типичные GitHub/AWS-ключи и PostgreSQL URI; совпадений нет. Проверка ограничена шаблонами и типами текстовых файлов, это не доказательство отсутствия любых секретов.
- Пароли хешируются PBKDF2-SHA256 с индивидуальной солью и 600 000 итераций; открытый пароль в базе не обнаружен. Сессии хранятся в виде SHA-256 от случайного токена. SQL-запросы параметризованы.
- Поддельная и истёкшая cookie не дают пользователя. Повторный вход с действующей cookie меняет токен и отзывает предыдущий. Выход отзывает текущий токен.
- Почта и пароли не сохраняются в IndexedDB/localStorage кодом приложения. Браузерный менеджер паролей находится вне этого механизма.

Действующие HTTPS/заголовки/CDN, подключение к PostgreSQL с проверкой сертификата, роль базы с минимальными правами, доступ к резервным копиям и логам, отсутствие записи тел запросов с паролями сторонними средствами, права и MFA аккаунта Vercel, защита от массовых запросов на уровне платформы.
